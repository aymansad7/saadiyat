# Listings Unification Audit — 2026-08-28

The editable record already has a stable global identity: `villa_listings.villaKey`, which is unique and includes the project/community path plus the unit or plot key. This record is the canonical operational override for an asking price, status, editable area values, rental status, owner contact, and internal notes. Every update already has an append-only `villa_listing_audit` entry and a project activity-audit event.

The availability read model correctly derives **NAS Luxury availability** from a `villa_listings` status of `available` without a second write path. It keeps independently curated `availability_listings` entries for Aldar, brokers, NAS, and manual sources separate, and deduplicates only matching source-plus-identity records. The Master Admin Listings page now makes that separation explicit: **Available now** is the source-aware inventory view, while **Operational profiles** is the set of editable canonical records.

The Interactive Map previously loaded property overrides only after authentication. It now requests the same listing read model for every viewer; the server returns the public projection to anonymous users and scope-permitted protected fields only to authorised users. This makes a saved status and price consistent on the Map, cards, and Listings. The map rebuilds marker closures whenever override data changes. The owner/tenant display remains an explicit user toggle rather than becoming visible automatically just because a user is authorised.

Visual verification confirmed that the Master Admin **Available now** workspace loaded 36 source-backed available rows and that **Operational profiles** reported 1,536 editable profiles. A first Map preview captured before the Google Maps tiles completed showed an empty canvas; a subsequent live browser check confirmed that Google Maps loaded normally. The anonymous browser correctly showed no property dots because it has no project access grant, rather than because the map failed.

Outstanding privacy follow-up: historical Hidd source data is currently imported into client-side pages for non-sensitive property facts and includes owner/tenant columns. Its visible rendering is gated, but the raw client import should be moved behind a server-side permission-filtered query in a future security-hardening pass so no sensitive source columns are bundled to unauthorised browsers.

Update: the source-data hardening follow-up is complete. A generated Hidd browser dataset holds property facts only, while a protected server procedure applies the caller’s `hidd` project and field grants before returning contact or tenancy facts. A clean browser session correctly displayed the email/password gate, then created a Master Admin session using a valid configured account. In that authorised session, the Map loaded its markers and showed owner/tenant fields only after the explicit **Owner & Tenant** toggle was activated and a Hidd villa card was selected. The original user-facing password value and all displayed personal contact data are deliberately omitted from this audit record.
